# TripGrant — demo recording script

**Target length:** 2–3 minutes. Record this separately from the pitch. Keep the network/test-funds label visible. The current demo uses a real local Solana validator and a custom TEST token, not public devnet USDC.

| Time      | Screen action                                                                                               | Narration                                                                                                                                                                                             |
| --------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:15 | Show Sponsor overview and the demo label.                                                                   | “This is TripGrant, a student travel grant workflow. These are synthetic events and receipts, with disposable funds on a real local Solana validator.”                                                |
| 0:15–0:45 | Create a new grant, fill event/destination/purpose, reserve 100, show fixed wallets and deadlines, fund it. | “The sponsor reserves one hundred test units for a specific student. The student, reviewer, cap and deadlines are fixed after funding. This budget is reserved; it has not been paid to the student.” |
| 0:45–1:15 | Switch to Student, open the new grant, use the synthetic receipt, submit 72.                                | “The student submits a seventy-two-unit expense. The original file stays private to the grant participants; its fingerprint and requested amount are recorded on Solana.”                             |
| 1:15–1:45 | Switch to Reviewer, download the receipt, show the hash, check eligibility, review 72.                      | “The designated reviewer checks the original evidence. A matching hash verifies the file match, not whether the expense is genuine. This demo receipt is explicitly synthetic.”                       |
| 1:45–2:10 | Show the settlement preview: student 72, sponsor 28. Approve and settle.                                    | “One transaction pays seventy-two to the student and returns twenty-eight to the sponsor. The grant is settled and cannot pay again.”                                                                 |
| 2:10–2:30 | Open confirmed transaction, show slot, success and program logs.                                            | “The displayed balances come from the program. Here is the confirmed transaction and the token program’s execution logs.”                                                                             |
| 2:30–2:45 | Show Quick guide’s expiry rule or explain it briefly.                                                       | “After the review deadline, anyone can trigger a refund, but only to the fixed sponsor. A zero approval also returns the whole budget.”                                                               |

Keep the distinction between local TEST tokens and devnet USDC explicit. If a public devnet deployment is completed before recording, use its actual transactions and Explorer link instead. The repository must match the recorded build. Never claim real students, adoption, partnerships or a security audit based on this demo.
